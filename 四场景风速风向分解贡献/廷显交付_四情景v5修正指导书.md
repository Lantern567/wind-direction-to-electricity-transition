## 三、具体实现

### 3.1 历史基准数据

使用你 v4 脚本已经加载的 1981–2010 逐日 12:00 UTC ERA5：
- `era5_baseline_daily_{region}_b1981_1990.nc`
- `era5_baseline_daily_{region}_b1991_2000.nc`
- `era5_baseline_daily_{region}_b2001_2010.nc`

对每个农场，构建：
- `p0_d[36]`：历史风向频率（各扇区小时数 / 总小时数）
- `p0_v_given_d[36, 19]`：各扇区内风速条件分布（19 档，与 FLORIS 分箱一致）
- `cdf_v_given_d[36]`：各扇区风速经验的 CDF 函数（用于分位数映射）

### 3.2 风速替换方法：分位数映射（quantile mapping）

**v4 用 `np.mean(ws_by_sector[si])`——这是错的。** 扇区平均风速丢失了扇区内方差，是造成 v3→v4 结果不一致的主要原因之一。

正确做法：对每个小时，保持风速在当年扇区内的分位数排名不变，但映射到历史基准分布。

```
对每个农场 × 扇区 d：
  构建历史基准 CDF：F_hist(v | d)  （从 1981-2010 数据）
  构建当年 CDF：     F_year(v | d)  （从当年 ERA5 数据）

P01 逐时计算：
  wd = 实际小时风向
  d = wd 所属扇区
  v_actual = 实际小时风速
  rank = F_year(v_actual | d)   ← 该小时风速在当年同扇区内的分位数
  v_mapped = F_hist^{-1}(rank | d)  ← 映射到历史基准的等分位数风速
  FLORIS.run(wd=wd, ws=v_mapped) → 该小时功率

P00 逐时计算：
  随机采样 wd_hist ~ p0(d)   ← 和 P10 一样的采样逻辑，复用 counterfactual 代码
  d_hist = wd_hist 所属扇区
  随机采样 v_hist ~ p0(v | d_hist)  ← 从历史条件分布中采样
  FLORIS.run(wd=wd_hist, ws=v_hist) → 该小时功率
```

**为什么用分位数映射而不是随机采样？**
- 分位数映射是**确定性的**——同一个输入永远得到同一个输出，不需要多轮 Monte Carlo 取平均
- 分位数映射**保留了风速时间序列的秩相关性**——原来风速排名第 80 分位的小时，映射后仍然是第 80 分位（按历史基准的风速值）
- 这是气候归因研究的标准方法

**P00 为什么用随机采样？** 因为 P00 的风向和风速都来自历史基准，没有需要保留的实际时序结构——P00 就是气候平均状态下的期望发电量。一次采样即可（对 P00 做 10 轮采样取平均以降低 Monte Carlo 噪声，10 轮 × 1,203 场-年 = 额外约 10 分钟计算）。

### 3.3 稀疏扇区处理

当某扇区当年样本数 N_d < 30 时，CDF 分位数映射不可靠。对该扇区做收缩：

```
λ = N_d / (N_d + 30)
F_shrunk(v|d) = λ × F_year(v|d) + (1-λ) × F_marg(v)
```

其中 F_marg(v) 是该农场所有扇区合并的边际风速 CDF。

### 3.4 代码改动清单

在 `task2_floris.py`（或你 counterfactual 的主脚本）基础上：

1. **新增函数 `build_historical_cdfs()`**：读取三 decade 基准 NC 文件，构建 p0_d、p0_v_given_d、F_hist^{-1}
2. **新增函数 `build_year_cdfs()`**：从当年 NC 文件构建 F_year（可按需只构建正在处理的年份）
3. **新增函数 `quantile_map_ws(v_actual, d_sector, F_year, F_hist_inv)`**：分位数映射
4. **新增函数 `sample_historical_ws(d_sector, p0_v_given_d)`**：从历史条件分布采样 WS（用于 P00）
5. **新增模式 `compute_P01_P00(farm_id, year, turbs, model, ...)`**：逐时循环，调用 FLORIS 库

**关键约束：**
- P01 和 P00 的 FLORIS 调用**必须使用和 counterfactual 完全相同的 `FlorisModel` 实例**（同一个 `create_floris_model()`，同一个 `reinitialize()` 参数）
- 电气损耗 ELETRICAL_LOSS 在最后乘，不要重复乘
- 轮毂高度修正 `(H/100)^0.11` 要和 counterfactual 一致

### 3.5 输出格式

`four_scenario_floris_aep_v5.csv`

```csv
farm_id,year,P11_kWh,P10_kWh,P01_kWh,P00_kWh
```

- P11 = counterfactual 的 `AEP_real_kWh`（直接复制）
- P10 = counterfactual 的 `AEP_baseWD_kWh`（直接复制）
- P01 = 新增 FLORIS 计算
- P00 = 新增 FLORIS 计算
