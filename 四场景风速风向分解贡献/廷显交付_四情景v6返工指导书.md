## 一、背景：v5 为什么还要返工

v5 的 P11 对拍通过了（0.000%），但学长发现了两个问题：

| 情景 | v5 用了什么 | 问题 |
|------|-----------|------|
| P11 | 逐时 FLORIS 库 | ✅ |
| P10 | 2014-2017 查找表 / 2018-2024 counterfactual | ❌ **算法混搭 × 2（查找表 vs CF、且 CF 本身是 Numba Gauss）** |
| P01 | 36×19 查找表 × 概率权重 | ❌ **和逐时 FLORIS 不在同一口径** |
| P00 | 36×19 查找表 × 10轮采样 | ❌ **系统性低估 ~3-4pp** |

**后果：(1) MS 有 51.8% 的能量来自查找表偏置，不是年际波动；(2) P10 的人造断崖在 v6 初版方案中仍无法消除，因为 counterfactual 用的是 Numba Gauss 而非 FLORIS 库。**

## 二、核心原则：四条街必须在同一口径（非常重要）

v6 初版最大的错误是假设 counterfactual 使用的是 FLORIS 库，实际不是。廷显核查确认：**`task2_counterfactual.py` 第 62-81 行使用的是 `@njit` 手写 Numba Gauss**，参数 k=0.05 硬编码，没有二次转向、没有横向速度、尾流叠加是自写的 loss² 求和——和 FLORIS 库 Gauss（ka=0.38×TI+0.004, sosfs, secondary_steering, transverse_velocities）是**两套不同的尾流模型**。

因此 v6 的 P10 必须从头全部重算，不复制 counterfactual 的任何数据：

```
           P11       P10       P01       P00
风速来源   实际年份   实际年份   历史基准   历史基准
风向来源   实际年份   历史基准   实际年份   历史基准
尾流模型   ─────────── 全部 FLORIS 库 create_floris_model() Gauss ───────────
功率曲线   ─────────── 全部 IEA 10MW 同一份 power_thrust_table ───────────
电气损耗   ─────────── 全部 ELECTRICAL_LOSS = 0.9215 ───────────
轮毂高度   ─────────── 全部 (H/100)^0.11 ───────────
数据来源   S3复制    FLORIS    FLORIS    FLORIS
                    逐时算    逐时算    逐时算
```

**四个情景——同一个尾流模型、同一套功率曲线、同一个 create_floris_model() 实例。差一个字都不是同一口径。**

## 三、具体改动

### 3.1 P10：全部重算（1,203 场-年）← 修正版关键变化

**v6 初版错了：** 初版说"2018-2024 从 counterfactual 复制"，但 counterfactual 用的是 Numba Gauss，不是 FLORIS 库。如果 2014-2017 用 FLORIS 库、2018-2024 用 Numba Gauss，相当于 v5 的"查找表 vs CF"断崖换成了"FLORIS vs Numba"断崖——廷显实测 mean=4.68pp, max=28.21pp，和 v5 的 4.6pp 断崖在量级上完全相同。

**修正方法：** P10 全部 1,203 个场-年，用 FLORIS 库逐时重算。不复用 counterfactual 的任何值。

```
对每个农场 × 年份：
  Round 1..10（与 P00 轮数一致）：
    对每个小时：
      ws = 实际小时风速（该年该小时的实际观测值，不经任何变换）
      wd = 从 p0(d) 中随机采样（历史气候基准的风向频率分布）
      注意：wd 在扇区内均匀展布，不要放在扇区中心
      FLORIS.run(wd=wd, ws=ws) → 该小时功率
    年累计 × ELECTRICAL_LOSS = 本轮 P10
  P10 = 10 轮均值
```

**P10 和 P00 的区别只有一个：风速来源。**
- P10：实际 WS × 历史 WD → 只替换了风向，风速保持实际值
- P00：历史 WS × 历史 WD → 风向和风速都替换为历史基准值

两者都是 10 轮 Monte Carlo（WD 采样），都用 FLORIS 库逐时计算。P10 和 P00 的 WD 采样逻辑应完全一致（同一个 p0(d) 分布、同一个扇区内均匀展布逻辑）。

**v5 counterfactual 的 P10 仍可参考**：作为交叉验证——v6 FLORIS 库 P10 与 v5 Numba Gauss P10 的差值，应该与 v4→v5 的 P11 差值（~2%）量级一致。如果差出 5pp 以上，说明还有别的问题。

### 3.2 P01：查找表 → 逐时 FLORIS + 分位数映射（全部 1,203 场-年）

（此节与初版一致，廷显已确认理解。）

```
对每个农场 × 年份：
  Step 1: 构建当年 CDF —— 对 36 个 WD 扇区，分别统计当年风速的经验 CDF
  Step 2: 构建历史 CDF —— 对 36 个 WD 扇区，分别统计 1981-2010 基准期风速的经验 CDF
  Step 3: 逐时循环 ——
    对每个小时：
      wd = 实际小时风向（不做任何变换）
      d = wd 所属扇区
      v_actual = 实际小时风速
      rank = F_year(v_actual | d)          ← 该小时在当年同扇区内的分位数
      v_mapped = F_hist^{-1}(rank | d)      ← 映射到历史基准的等分位数风速
      FLORIS.run(wd=wd, ws=v_mapped)       ← 用 FLORIS 库算该小时功率
  年累计 × ELECTRICAL_LOSS = P01
```

**稀疏扇区处理（收缩估计）：**
```
λ = N_d / (N_d + 30)
F_shrunk(v|d) = λ × F_year(v|d) + (1-λ) × F_marg(v)
```
其中 F_marg(v) 是该年所有扇区合并的边际 CDF。N_d=1 时 λ≈0.03，CDF 几乎退化为边际分布；N_d=700 时 λ≈0.96，接近纯经验 CDF。

### 3.3 P00：查找表 → 逐时 FLORIS + 历史采样（全部 1,203 场-年）

（此节与初版一致，廷显已确认理解。）

```
对每个农场 × 年份：
  Round 1..10：
    对每个小时：
      wd = 从 p0(d) 随机采样（历史风向频率，扇区内均匀展布）
      d = wd 所属扇区
      v = 从 p0(v|d) 随机采样（从历史原始 WS 值中按频率随机抽取）
      FLORIS.run(wd=wd, ws=v) → 该小时功率
    年累计 × ELECTRICAL_LOSS = 本轮 P00
  P00 = 10 轮均值
```

**P00 WD 采样的 p0(d) 与 P10 必须完全一致。**

### 3.4 FLORIS 调用规范（非常重要）

以下五项必须和 **S3** 完全相同（不是 counterfactual——它用的是 Numba Gauss）：

1. **尾流模型**：`create_floris_model()` —— FLORIS 库 Gauss，不是手写 Numba
2. **功率曲线**：IEA 10MW，同一份 `power_thrust_table`
3. **电气损耗**：`ELECTRICAL_LOSS = 0.95 × 0.97 = 0.9215`
4. **轮毂高度修正**：`ws_hub = ws_100m × (hub_height / 100) ^ 0.11`
5. **湍流强度、风切变**：复用 S3 的 TI/farm 配置（`get_ti_for_farm()` 或等效逻辑）

**如果需要参考代码**：看 S3 的 FLORIS 调用，不要看 task2_counterfactual.py。

## 补充说明：为什么 counterfactual 不能继续用

以下是廷显发现的 `task2_counterfactual.py` 与 FLORIS 库的关键差异：

| | counterfactual（第 62-81 行） | FLORIS 库 Gauss |
|---|---|---|
| 实现 | `@njit` Numba 手写 | C++/Python FLORIS v4.6 |
| 尾流衰减 k | 0.05 硬编码 | 0.38×TI + 0.004（动态） |
| 二次转向 (secondary_steering) | 无 | 有 |
| 横向速度 (transverse_velocities) | 无 | 有 |
| 尾流叠加 | 自写 loss² 求和 | FLORIS 库 SOSFS |
| TI 依赖 | 无（k 与 TI 无关） | 有（k 随 TI 变化） |

这是两套不同的物理模型。把它们拼在一起的 P10，不是"同一口径"——验证项 #2 和 #3 就是为了确保这个问题在 v6 中不再存在。

**底线：P10 必须全部用 FLORIS 库重算。不复制 counterfactual 的任何值。**
